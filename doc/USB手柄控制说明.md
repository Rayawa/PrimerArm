# USB 手柄控制说明

适配 USB Gamepad（0810:0001）、香橙派 AI Pro 和当前 Arm_Lib。这是本次新增的控制程序，不是厂家原装功能。2026-09-24 按用户要求调整了布局：普通摇杆操作无需 L1，L1/R1 只用于切换特定关节。新版布局已做离线验证，需上传到板端使用。

## 上传

在 Windows PowerShell 执行：

```powershell
scp "A:\arm\gamepad_arm_control.py" HwHiAiUser@192.168.137.100:/home/HwHiAiUser/
```

先退出旧手柄程序、垃圾分类、堆叠、校准 Notebook 内核和其它机械臂控制脚本。dofbot_server 可以保留。手柄控制无需 ROS 服务、摄像头或 NPU。

## 首次识别数字键

在香橙派终端执行，保持手柄 ANALOG 模式，摇杆回中：

```bash
sudo /usr/bin/python3 /home/HwHiAiUser/gamepad_arm_control.py --configure-buttons
```

按提示看手柄上印刷的数字：先按实体数字 1、松开，再按数字 1 确认；随后按实体数字 3、松开，再按数字 3 确认。不要移动摇杆。两次收到的编号一致才接受该键。这一步不访问机械臂，编号保存到脚本旁的 gamepad_buttons.json。若当前实际是 2/4 键控制夹爪，必须执行以上 --configure-buttons 命令覆盖旧映射，仅上传脚本不会修改旧配置。识别中途退出不会覆盖原配置。

## 按住连续模式（新增）

### 2026-09-24-comm3 通信时序修订

启动第一行应显示 `控制脚本版本：2026-09-24-comm3`。板端对照中，comm2连续模式仍发生过失联，低频查询三轮正常，底座8次单步动作正常。这支持进一步比较读写频率，但还不能证明根因或长期稳定。

连续模式新增 `--hold-rest-ms 400`，默认每段150ms运动完成后静默400ms再查询；查询应答等待50ms，查询后再留50ms才允许下一条运动。全部关节共用这个时序。支持50–1000ms，单步模式忽略此参数。等待期间每10ms检测手柄；松手后不发送下一段，计划内的静默不再误判为循环卡顿。

静默期间的行程不补做，每次位置积分仍最多计入0.2秒。以 `--speed 10 --hold-rest-ms 400` 为例，推满时连续运动的平均速度约3°/秒，实际取决于反馈与负载，动作可能有明显停顿。本版保留小段行程和按住控制，用于验证降低读写频率的效果；尚未在板端验证故障是否消失。

任一关节原始反馈为0、无效数据或I²C读写失败，全部关节立即暂停后续读写5秒，程序保持运行。期间推杆、按键、换关节都不会触发额外查询。5秒后只在摇杆回中、数字键松开时读取出错关节；仍失败则再静默5秒。连续两次反馈有效且稳定后显示“通信复查成功”，仍需回中后重新操作。不会恢复先前的长按、补发运动或重设已确认的范围基准。

写入使用与随附Arm_Lib相同的舵机数据包，但会捕获并处理I²C异常，避免原驱动仅打印错误而继续运行。本版离线测试核对了全部合法整数角度的数据包、运动与查询间隔、跨关节静默、松手不续发及恢复不补发；实际通信稳定性仍需板端观察。

上传新版并退出旧控制程序后运行：

```bash
sudo /usr/bin/python3 /home/HwHiAiUser/gamepad_arm_control.py --move --mode hold --joints 1 2 3 4 5 6 --span 90 --speed 10 --hold-rest-ms 400
```

这是按住时间决定运动幅度的模式。保持原按键布局：普通摇杆无需 L1；腕部使用 L1 加左摇杆上下，末端旋转使用 R1 加右摇杆左右；数字 1 按住张开、数字 3 按住闭合。摇杆按超过死区后的推幅调节速度，数字键使用满幅输入。实际平均速度受静默间隔、反馈读取和舵机负载影响，推满也可能明显低于设定上限。

--speed 10 表示请求最高约 10°/秒；--span 90 将各关节限制在启动位置 ±90°及接口合法范围内（1/2/3/4/6 号为0–180°，5号为0–270°）。例如底座起始40°，本次范围为0–130°，不会得到负角度。--step 在此模式不参与计算，不再每次固定移动 16°。角度指令为整数，分辨率约 1°，不支持任意小数角度精度。若手柄只上报中心/端点，推幅调速不会产生中间档位。

启动时没有有效初始反馈的关节标记为“尚未就绪”，不会使整个连续模式退出。发生通信故障时，上述全局静默优先于所有初始化与操作；恢复通信后，摇杆回中且数字键松开时，每3秒轮流检查一个未就绪关节。尝试操作未就绪关节也只检查反馈，不发运动。首次取得稳定有效角度才锁定该关节的范围基准，已确认的基准不会重设。初始化或复查期间的操作不会补发，恢复后需回中再重新操作。

这一机制不能保证修复控制板失联。如果一直读到原始值0，应保留新版输出，继续排查通信、控制板状态及其它总线访问者；0不能作为当前位置使用。

启动后先回中、松开数字键，看到就绪再操作。按住不必反复回中；松手后停止续发。一次仍控制一个关节，切换方向、关节或组合键前先回中并松开数字键，组合键在回中时先按好。斜推、多输入冲突、组合键变化会停止续发。

连续动作拆成 150 ms 的短段，新的运动目标限制在最新反馈附近 4°内。反馈滞后时减速等待并丢弃积累的更远目标，不再因为普通滞后而退出。正常松手后最后一段仍可能完成，不是硬件瞬时急停。程序会等待最后一段结束并核对反馈，再恢复就绪。到达角度边界后停止续发，回中再反向可离开边界。

持续约0.8秒没有至少1°的进展、且目标仍领先反馈至少2°时，会暂停并重新读取稳定角度；若仍未达到目标，判为“疑似受阻”。夹爪闭合受阻时锁住继续闭合，松开再按3也不再挤压，1号数字键张开和其它关节仍可操作。只有反馈确认实际张开至少2°后才解除闭合锁定；仅按一下张开键但没动不解锁。其它关节受阻也只锁住对应方向，确认反向移动2°后解除。

受阻时下发一次已确认的当前角度作为保持目标，以撤销原来未达到的更远目标；不关闭扭矩。该判断只基于角度进展，没有力传感器，不能区分正常夹住物体、碰撞或机械卡住，也不保证夹持力大小。方向锁只保存在当前进程中，不要重启来绕过锁定。

连续过程中遇到原始反馈0或I²C异常，进入上述全局静默与复查；角度不稳定、反馈越界等动作检查失败则取消当前动作，主程序继续运行。下一次操作必须重新取得有效稳定反馈，不能用旧角度代替。比计划查询时间额外延迟超过0.5秒会丢弃待发动作，不积压补做。手柄真正拔出、Ctrl+C、无法打开机械臂总线或检测到其它控制程序仍会退出；不自动恢复运动。

去掉 --move 可查看映射预览，预览不模拟舵机角度。旧的 gamepad_preview.py 布局不同，不用于验证新版。

## 单步模式（保留）

不指定 --mode 时仍使用已验证的单步模式，也可以显式加 --mode step：

```bash
sudo /usr/bin/python3 /home/HwHiAiUser/gamepad_arm_control.py --move --joints 1 2 3 4 5 6 --step 16 --span 90 --speed 10
```

每次推杆或按数字键只执行一步，默认速度 10°/秒，16° 对应 1600 ms，比原先的 3200 ms 缩短一半。每个关节限制在启动位置附近 ±90°，同时遵守驱动接口角度范围。程序不自动复位，不切换扭矩。夹爪数字键也使用相同步长和速度设置。新版持续受阻锁定和仅取消当前动作的行为适用于连续模式；单步模式仍采用原来的动作后检查。

--speed 单位为度/秒，支持 5–20，默认 10；例如 --speed 5 恢复此前的运动时间，--speed 20 对应 16°用时 800 ms。任何单步动作都不少于 800 ms，小步长时实际速度会受这个最短时间限制。这里设置的是下发给舵机的运动时间，实际效果取决于负载和舵机。

若只看映射输出，使用同一脚本并去掉 --move。旧 gamepad_preview.py 使用之前的布局，不用于验证新版。

## 操作布局

| 输入 | 动作 |
| --- | --- |
| 左摇杆上下，无需 L1 | 2 号大臂 |
| 左摇杆左右，无需 L1 | 1 号底座 |
| 右摇杆上下，无需 L1 | 3 号小臂 |
| L1 + 左摇杆上下 | 4 号腕部，替代大臂动作 |
| 数字 1 | 6 号夹爪张开（角度减小） |
| 数字 3 | 6 号夹爪闭合（角度增大） |
| R1 + 右摇杆左右 | 5 号末端旋转 |
| 右摇杆左右，未按 R1 | 不动作 |

摇杆向左/上使角度减小，向右/下使角度增大；这是关节角度方向，不是末端空间方向。单步模式每次开合一步，连续模式按住持续开合，都不是一键自动完全张开/夹紧。以下短按规则仅适用于单步模式。

先让两个摇杆回中、松开数字键，等待“就绪”提示，再单方向短推摇杆或单独短按数字键。识别到操作后会显示“收到”，此后正常松手不会取消这一步。下一步前再次回中并松开数字键，等待重新显示“就绪”。无需每次松开 L1/R1；使用组合键时，在摇杆回中状态先按住相应肩键，再推杆。

旧版在角度读取后要求输入仍保持不变，短按容易被取消；新版保留已识别的单步动作，轮询间隔缩短到 10 ms。默认速度下，16°运动 1.6 秒，再等待 0.4 秒并读取反馈，约 2 秒后恢复就绪；反馈重读时会延长等待。执行中不接受其它操作，也不排队补做。若检查耗时超过 0.5 秒、设备断开、出现其它方向或冲突输入，则不发送这一步。短按必须被轮询捕捉到，极短触碰仍可能遗漏。

程序一次只接受一个动作。斜推、多轴同时输入、同时按两个夹爪键、推杆时按夹爪键，均取消本次动作；回中并松开数字键后可重新操作。推杆途中切换 L1/R1 也会取消尚未发送的动作。

## 范围和停止

- 单步模式 --step 支持 1–16°，--span 支持 1–90°且不得小于步长；--speed 支持 5–20°/秒，单步动作时间不少于 800 ms。连续模式不用 --step，短段时间为150ms。默认仅启用底座、单步模式、16°步长、±90°范围、10°/秒，以上命令显式启用全部关节。
- 目标越界不发越界动作，可回中后反向操作或控制其它关节。范围不会随动作重算。连续模式反馈异常只取消当前动作；单步模式反馈无效、不稳定、越界或偏离目标超过2°仍停止程序。
- 端点读数按原版 Arm_Lib 先转换为整数角度，再检查范围；原始位置 3104 对于 3 号关节对应 0°。
- 原始反馈值0不是有效的0°角度。新版实物通信遇到一次0就进入全局静默，不再连续快速重读4次。复查要求连续两次有效且相差不超过2°，不重发运动指令，也不使用上次角度代替反馈。
- 启动时已推杆或按住数字键不会立即动作，必须先回中并松开数字键。单步模式一直保持输入不会连发；连续模式只有保持输入才续发。均不排队补发动作。
- 普通摇杆无需 L1，因此运行期间拨动摇杆就可能移动机械臂。松开摇杆、数字键或按 Ctrl+C，不会中断已经发给控制板的单步动作。程序退出不释放扭矩、不复位。
- 固定底座并保持活动范围无障碍。角度限制不是碰撞检测；不要反复重启来绕过范围限制。程序检测常见分拣/堆叠进程，但不能发现所有其它 I²C 控制者。
- 自动查找手柄，不固定 /dev/input/event1。手柄断开会退出；运行期间保持 ANALOG 模式。

离线测试文件为 test_gamepad_arm_control.py、test_gamepad_hold.py 和 test_gamepad_transport.py，覆盖按键映射、单步与连续控制、夹爪受阻、边界、全局通信时序、静默与恢复；不执行真实硬件动作。
