# 亚博语音模块接入核查

核查日期：2026-09-26。用户两块蓝白模块分别为语音识别和语音合成播报，接在机械臂扩展板上，非直接接香橙派。用户照片中的接线手册为 Jetson Nano 版本。照片不足以确认每根实际接线与插座丝印，也尚未取得扩展板原理图。

## 官方来源与已确认协议

- https://github.com/YahboomTechnology/Asr/blob/master/main.ts
  - I2C 地址 0x0F；0x08 为识别结果，0x0A 为词条数量。
  - 查询：写一个寄存器选择字节，等待 150ms，再读一个字节。
  - 支持添加词条及循环、口令、按键识别模式。词条格式、容量尚需配套说明确认。
- https://github.com/YahboomTechnology/Asr_V3/blob/master/main.ts
  - 同为 0x0F，读取结果/数量方式相同；新增 0x0B 固件版本、0x0C 忙闲。
  - 新旧添加词条协议不同，不能在硬件版本未确认时直接清空或写入词条。
- https://github.com/YahboomTechnology/Speech-Synthesis-module
  - README：XFS5152CE，I2C 通信，可合成中文和英文文本，支持 GB2312/GBK/BIG5/UNICODE。
  - `5.Jetson nano course/Broadcast English text/English_speech.py`：SMBus(1)，地址 0x50，逐字节写入并间隔 10ms。
  - 状态查询帧 FD 00 01 21，随后等待 50ms 读一个字节；状态定义 0x4A 初始化、0x41 命令正确、0x45 命令错误、0x4E 忙、0x4F 空闲。
- https://github.com/YahboomTechnology/Speech/blob/master/main.ts
  - 明确区分 NEW_ADDR=0x30 与 OLD_ADDR=0x50；这是主机目标地址选择，不是给模块重设地址。

## 与当前板端信息的关系

现有 Arm_Lib v0.0.5 访问 I2C-7 / 0x15，没有语音接口。USB 列表只有相机、手柄、无线网卡，未见 USB 语音/串口设备。I2C 模块不必作为 USB 或 tty 设备出现。

扩展板插口是否直接引出 40PIN 上的 I2C，仍须原理图或板端响应证据核实。先仅在已使用的 I2C-7 上对 0x0F、0x30、0x50 作少量接收字节检查，不访问机械臂 0x15，不作全地址或全总线扫描。响应只表明该地址有设备应答，不能独立证明型号；单次读失败也不能独立证明模块损坏。

后续需要用户返回定点测试结果，再做 ASR 已有词条数量查询、播报状态/短文本测试。尚未在实物执行任何语音读写。不能把 Jetson SMBus(1) 原样用于香橙派，也不能因地址无响应直接改线或刷固件。

## 板端后续结果

用户执行 I2C-7 上的单次 read_byte：0x0F、0x30、0x50 全部 Errno 110 Connection timed out。用户确认两个语音模块灯亮。此结果仅能确认直接读取未成功，不证明模块损坏或整条总线失效。下一步对照 0x15 控制板版本查询，再按原厂 0x0F 写单字节 0x0A、等待150ms、读取一字节的方式检查词条数量。

另下载并核对官方文档 `https://github.com/YahboomTechnology/dofbot-jetson_nano/blob/master/06.Preparation/1.Introduction%20of%20expansion%20board.pdf`，本地 `../04_排查原始材料/voice_research/expansion-board.pdf`。第1页图明确区分两个4针 I2C 插口与靠近 K1 的2针风扇接口。用户照片有线缆遮挡，不能断言两块模块均接对或接错；灯亮也不能证明数据连通。
