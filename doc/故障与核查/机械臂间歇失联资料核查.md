# 香橙派 AI Pro / DOFBOT 间歇失联资料核查

核查日期：2026-09-24。本文依据用户日志、照片、随附厂家手册和 Arm_Lib 0.0.5 源码；未连接实物、未修改板端配置、未发送运动或复位指令。

公开网页检索未完成：浏览器打开搜索页的动作三次被自动审批服务 HTTP 503 阻止，页面均未打开。这是服务故障，不是安全拒绝。因此本文不声称找到或排除了公开同类故障案例。

## 1. 现象与能够支持的结论

| 已有证据 | 支持的判断 | 不能据此认定 |
| --- | --- | --- |
| 故障时三轮版本寄存器都返回20，没有报告I²C读写异常 | 底板的本地寄存器查询仍有一致回应，主机到板子的I²C并非完全无响应 | 电压、波形或所有I²C事务都正常 |
| 六个舵机的状态和原始位置同时为0 | 底板未提供有效舵机应答，应查共用路径及底板处理状态 | 六个舵机全部损坏，或角度真的为0° |
| 保留机械臂独立供电，香橙派断电后底板按键能归正 | 香橙派上电/访问状态与故障有关联 | 已证明反向供电，或已证明软件是唯一原因 |
| 稍后同一脚本和参数能连续正常工作，也曾自行恢复 | 故障间歇发生 | 故障已经修好；某个固定角度必然触发 |
| 底座8次单步动作正常 | 该次姿态、负载和动作节奏下工作正常 | 所有单步操作长期稳定；连续指令频率已被证明是根因 |
| comm2及comm3都曾失联，comm3也曾长时间正常 | 现有节奏调整没有根治故障 | 继续缩短/延长一个等待参数一定有效 |

重点应放在底板内部的舵机通信处理、舵机侧供电/共地、共用线束，以及香橙派连接带来的电气或命令影响。I²C间歇干扰仍不能排除。没有匹配底板的原理图和实测电压/波形，不能继续缩小到一个确定部件。

## 2. 已核实的连接、电压和协议

### 香橙派端

来源：[Orange Pi AI Pro用户手册v1.2](../../OrangePi/doc/OrangePi_AI_Pro_昇腾_用户手册_v1.2.pdf)，3.13及3.14.3节，印刷页81–83、87–88（PDF第87–89、93–94页）。

- 物理3号脚是SDA7，5号脚是SCL7；驱动使用 `/dev/i2c-7`。
- 物理2、4号脚是5V，1、17号脚是3.3V，6号等多个针脚为GND。
- 普通GPIO信号电平为3.3V。
- 27、28号脚属于I²C6，默认电压为1.8V；不能把改用I²C6当作随手替换。
- 8、10号脚默认是调试串口，且与Micro USB调试串口相连。没有底板对应接线图，不能认定它们造成冲突，也不建议盲目关串口或改变复用。
- 系统默认启用手册标明的I²C功能；当前已经多次读到有效反馈，无需重新“启用I²C”。

### 机械臂端

来源：[配套实验手册](../02_实验手册/香橙派AIpro机械臂垃圾分类实验4.7.docx)，硬件连接章节。

官方方案明确采用完整40PIN排线，并要求开发板、机械臂分别接入电源。香橙派侧接头凸起朝外、针位对齐；机械臂侧接头凸起对准插座凹槽。所有接线操作均在两边断电后进行。

40PIN里确实有电源脚，但该说明没有给出这块底板的供电隔离电路。底板独立电源关闭后仍亮灯，支持“仍有电路得到供电”，不能独自证明不正常回灌，也不能证明舵机供电正常。不应在缺少原理图时剪线、拔除5V针脚、加二极管或改线序。

本地 `QSM565DP-WFPI_SCH_V1.2_20250415.pdf` 标识为Quectel QSM565DP平台，并不是已确认匹配的香橙派AI Pro/DOFBOT底板原理图；本次没有把它用于判断供电路径。

### 配套驱动

来源：[Arm_Lib.py](../../机械臂/robot_arm_dependency/0.py_install/Arm_Lib/Arm_Lib.py)。

| 操作 | 配套源码中的实现 | 对当前问题的意义 |
| --- | --- | --- |
| 主机接口 | `smbus.SMBus(7)`，地址`0x15` | 主机控制链路是I²C，不是摄像头USB |
| 版本查询 | `Arm_get_hardversion()`，寄存器`0x01` | 原始20按驱动拼成字符串`0.20`，不等于已确认某个固件发布版本 |
| 舵机状态 | `Arm_ping_servo()`，寄存器`0x38` | 源码注明正常`0xDA`即218；0表示没有数据；其他值为舵机错误 |
| 舵机位置 | `Arm_serial_servo_read()`，寄存器`0x31`到`0x36` | 原始0返回None，不能用作有效角度 |
| 控制板复位 | `Arm_reset()`，向`0x05`写1 | 确实有该接口，但文档未说明复位时姿态/扭矩行为，不应加入自动重连重试 |
| 按键模式 | `Arm_Button_Mode()`，默认/学习模式 | 是底板按键用途设置，不是总线重连设置 |
| 产品选择 | `Arm_Product_Select()`，源码注释为产品颜色 | 没有证据表明它是通信兼容模式 |
| 扭矩、ID、偏移 | 有独立写入接口 | 不能用于盲目修复失联，可能改变机械臂行为或配置 |

配套单舵机写入函数捕获异常后只打印`I2C error`，不向调用者抛出；现有comm2/comm3使用相同数据包并让写失败进入暂停处理。未发现配套驱动提供自动断链时间、连接保活或设置I²C时钟的方法。

## 3. 相关设置和已记录的软件更新

### 通信休息时间不是I²C时钟

手柄脚本的 `--hold-rest-ms` 是运动段结束后的休息时间。改变它只改变应用层访问节奏，不改变I²C总线的时钟频率，也不修改底板固件。

实际I²C时钟需结合当前设备树、驱动配置或示波器测量确认。本地手册未提供可直接用于本案的调速命令，不应照搬树莓派的 `dtparam=i2c_arm_baudrate`。

随附垃圾分类动作代码常采用500ms、1000ms运动并等待相应时长；这只是例程用法，不是厂家对最小运动时间或最大查询频率的保证，不能据此宣布150ms不受支持。

### 风扇

来源：同一香橙派用户手册3.19节，印刷页126–127（PDF第132–133页）。风扇是12V四针PWM风扇，默认自动模式。手册给出了以下只读查询：

```bash
sudo npu-smi info -t pwm-mode
sudo npu-smi info -t pwm-duty-ratio
```

`pwm-duty-ratio`是控制占空比，不是实际转速测量，不能单凭该数值确认风扇机械运转正常。手册示例中的15%也不是用户设备的实测值。

手册确实列出手动调速：先 `sudo npu-smi set -t pwm-mode -d 0`，再 `sudo npu-smi set -t pwm-duty-ratio -d 100`；恢复自动模式为 `sudo npu-smi set -t pwm-mode -d 1`。本次未执行任何设置。应先记录当前模式、温度与故障时刻，避免一次改变多项条件。

手册更新历史记录了2024-09-23系列镜像“优化PWM风扇的自动温控机制”；没有写明这与机械臂失联有关，也不能凭Ubuntu 22.04版本号判断用户镜像是否含该修正。

### 休眠及引脚复用

配套实验手册3.2.2要求禁用系统休眠，目的是避免SSH断开。可先只读检查：

```bash
systemctl is-enabled sleep.target suspend.target hibernate.target hybrid-sleep.target
```

故障时SSH、Python输出及控制板版本查询仍正常，和整机已休眠的表现不一致。没有证据时，不把禁用休眠当成本次修复。

用户手册记录2025-09镜像默认打开CAN2，对应物理26、31脚；机械臂驱动的I²C7是3、5脚。尚未确认底板其他信号连接，不能据此认定CAN2冲突或直接关闭它。

## 4. 下一步需要的证据

暂停新增运动测试和进一步加速，优先在故障发生后、重启前采集以下只读信息。这些命令不向机械臂地址发送运动、扭矩或复位指令。

```bash
date -Is
uptime
sudo npu-smi info -t pwm-mode
sudo npu-smi info -t pwm-duty-ratio

for z in /sys/class/thermal/thermal_zone*; do
    [ -r "$z/temp" ] || continue
    printf '%s: ' "$(cat "$z/type")"
    awk '{printf "%.1f C\n", $1/1000}' "$z/temp"
done

sudo journalctl -k -b --since '-15 min' --no-pager | grep -Ei 'i2c|smbus|timeout|thermal|overheat|voltage|under.?volt|usb.*(reset|disconnect)' | tail -n 100
```

没有匹配的内核日志不等于没有电气故障。thermal_zone只显示系统导出的温度点，不一定包括所有芯片，更不包括底板和所有舵机。

硬件方面应请厂家按准确板号核对：40PIN的5V/3.3V与独立电源是否隔离；中间小板的功能及供电连接；底板是否有舵机总线固件异常记录。需要测量时，应由能正确辨认测试点的人比较正常/故障状态下的舵机电源和逻辑电源，并检查共地、SDA/SCL波形；目前照片不足以指导具体探针接触位置。

## 5. 可给厂家的问题描述（未发送）

香橙派AI Pro通过40PIN/I²C7访问DOFBOT控制板，地址0x15，配套Arm_Lib 0.0.5。正常时六个舵机状态218、位置有效。间歇故障时，版本寄存器0x01仍稳定返回20，但0x38查询六个舵机均为0，0x31–0x36原始位置均为0；3ms、50ms应答等待及停止运动后的低频检查结果一致。排查时未发现其他进程打开/dev/i2c-7。部分故障会自行恢复；一次保持机械臂独立供电、只断香橙派电源且保留排线后，底板归正键恢复。请确认该底板40PIN供电隔离设计、与香橙派全40PIN连接的兼容要求、允许的运动/查询节奏、是否有相关固件问题或更新，以及Arm_reset的扭矩和动作行为。

需补充底板和中间模块的准确型号、板号、当前系统镜像标识。不要把版本寄存器20直接当成已核对的固件发布号。
