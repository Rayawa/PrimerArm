## 2 控制原理

    Windows --SSH--> 香橙派
                       |
              USB 摄像头 -> YOLOv5 OM 模型（NPU）
                       |
                图像坐标转抓取坐标
                       |
                /trial_service 计算关节角
                       |
                Arm_Lib -> I²C -> 扩展板 -> 舵机

- dofbot_server 只计算正逆运动学，不发送舵机动作。服务存在也不等于已经验证所有求解过程。
- block_cls 负责识别、分拣；启动初始化时会复位机械臂。
- color_stacking 负责识别、堆叠；启动也会复位。
- dofbot_moveit.launch.py 启动 RViz、URDF 和关节滑块，没有把滑块连接到 Arm_Lib。三维模型动不等于实物动。
- 只需手动设置关节角度时，无需摄像头、ROS、YOLO 或 NPU。

当前两个 coco_names.txt 只有 Fish_bone、Newspaper、Syringe 三类。应使用配套模型和对应图案积木。动作脚本列出更多垃圾名称，不代表模型能识别那些类别。其它目录的 MiniCPM 或普通 YOLO 模型不能改名充当专用模型。

## 3 接线及舵机不动作的排查

官方要求开发板和机械臂分别使用配套电源，机械臂扩展板开关置 ON。40PIN 排线连接两者，USB 摄像头接开发板。需要重插排线时先断开两边电源，按 AI Pro 图片核对方向。蓝灯亮、能读角度，均不能单独证明舵机动力供电正常。

驱动固定使用 smbus.SMBus(7)，地址 0x15。板级手册确认 I²C7 的 SDA 为物理 3 号针、SCL 为物理 5 号针，设备节点为 /dev/i2c-7。物理针号与 GPIO 编号不同；已有配套排线不必改成散线。

| 驱动接口 | 含义 |
| --- | --- |
| Arm_serial_servo_read(id) | 读 1～6 号角度；失败返回 None。 |
| Arm_ping_servo(id) | 舵机状态；源码注释规定正常返回 0xda。 |
| Arm_get_hardversion() | 扩展板硬件版本。 |
| Arm_serial_servo_write(id, angle, time) | 单关节控制，时间单位毫秒。 |
| Arm_serial_servo_write6_array(joints, time) | 六关节控制，顺序为基座、大臂、小臂、腕部、末端旋转、夹爪开合。 |
| Arm_serial_set_torque(1) | 打开扭矩；参数 0 关闭扭矩。可能使多个关节恢复保持力。 |

1、2、3、4、6 号接口范围为 0～180°，5 号为 0～270°。这是接口范围，不保证所有组合姿态都安全；驱动也没有自动避障。

此前你读到 89、90、90、90、90、175°，但观察不到运动。可能原因包括独立供电、扭矩关闭、堵转或保护、实际硬件与驱动不匹配、其它程序同时控制。不能从代码断定唯一原因。

推荐先核对电源和接线，然后读取各舵机 status 和硬件版本，最后再做扭矩使能、小角度测试。扭矩接口来自配套驱动，但“当前扭矩一定关闭”尚未证实。使能可能影响多个关节，应先确认机械臂固定、各关节周围无障碍。不要继续盲目扩大角度或随意重设舵机 ID、零点偏移、驱动板参数。

## 6 官方案例的剩余步骤

### 6.1 推理环境

先验证 acl、aclruntime 和 ais_bench.infer.interface.InferSession 可用。官方教程单独安装推理工具，原始命令如下，只有确认缺项且与当前 CANN 匹配时再用：

    python3 -m pip install -v 'git+https://gitee.com/ascend/tools.git#egg=aclruntime&subdirectory=ais-bench_workload/tool/ais_bench/backend'
    python3 -m pip install -v 'git+https://gitee.com/ascend/tools.git#egg=ais_bench&subdirectory=ais-bench_workload/tool/ais_bench'

这是手册中的仓库路径，本次未验证其当前可用性与板端 CANN 兼容性。不要无条件覆盖已有推理环境。安装日志提到 ml-dtypes 缺失，应按 CANN 版本处理，不能为此无约束升级 NumPy。getopt、inspect、multiprocessing 是 Python 标准库，不安装 PyPI 同名包。

NPU Alarm 要查看具体原因，不能仅凭温度数字判断。应先单独测试模型加载或离线图片推理，而不是用会自动复位的 block_cls 作为首次推理检查。

### 6.2 模型

手册模型地址如下，本次未联网验证其可用性及与当前 CANN 的兼容性。确认缺少模型后，在板端 root 终端下载：

    cd /root/ros2_robot_arm/ros2_ws
    curl -fL --connect-timeout 15 --max-time 300 \
      'https://eduhicomputing.obs.cn-south-1.myhuaweicloud.com/document/robot/yolov5s_bs1.om' \
      -o /root/ros2_robot_arm/yolov5s_bs1.om.part

只有下载成功、文件完整后再执行：

    install -m 0644 /root/ros2_robot_arm/yolov5s_bs1.om.part src/dofbot_garbage_yolov5/dofbot_garbage_yolov5/model/yolov5s_bs1.om
    install -m 0644 /root/ros2_robot_arm/yolov5s_bs1.om.part src/robot_arm_color_stacking/robot_arm_color_stacking/model/yolov5s_bs1.om
    source /opt/ros/humble/setup.bash
    colcon build
    source install/setup.bash

setup.py 会把模型和配置安装到 install/<包名>/share/<包名>/，所以新增模型或修改配置后重新编译。

### 6.3 相机校准

先完成舵机执行验证、模型加载验证与摄像头采图。官方校准 Notebook 初始化也会加载模型、发送复位动作。

1. 固定机械臂与标定地图，让摄像头看到完整十字框。
2. 将分拣包 utils/garbage_identify.py 和 utils/npu_utils.py 的 CALIB_MODE 临时从 False 改为 True。
3. root 终端已加载 ROS、CANN，使用系统 Python 启动 Jupyter：

       cd /root/ros2_robot_arm
       /usr/bin/python3 -m notebook --allow-root --ip 192.168.137.100 --no-browser

4. Windows 浏览器打开终端地址并用 token 登录。进入 ros2_ws/src/dofbot_garbage_yolov5/tools/ 的相机校准 Notebook，选择系统 Python 3.10 内核。当前工程文件名乱码但 ipynb 仍存在，OrangePi 重复工程中中文名正常。
5. 运行前清空活动范围，因为它会复位。点击 calibration_model，调整 joint1、joint2、threshold，使蓝框覆盖十字框，再点击 calibration_ok。
6. 确认写入 config/XYT_config.txt 与 config/dp.bin。dp.bin 实际存四个 int32 坐标点、形状 4×2，不是最终 3×3 透视矩阵。
7. 点击 Exit 并关闭 Notebook 内核、停止 Jupyter，释放摄像头。将两处 CALIB_MODE 改回 False，再编译。
8. 分拣抓取准确后，把 XYT_config.txt、dp.bin、offset.txt 同步至堆叠包 config，再编译。摄像头、地图、底座相对位置改变后重新校准。

### 6.4 夹爪和补偿

当前 garbage_grap.py:16、stacking_grap.py:17 的 self.grap_joint 仍为 130。实验手册 5.5 节示例改为 120，并将部分 500 ms / 0.5 s 调为 800 ms / 0.8 s。应按夹爪与积木实际调整，120 不保证适用于所有设备。运动时间增加时，应同步增加等待时间。

offset.txt 第一行为 Y 前后补偿，第二行为 X 左右补偿，当前为 0.016、0.01。教程示例每次调整 0.002，坐标单位米，即 2 mm。一次只改一个方向，观察真实误差，不能直接套用别人的最佳值。

## 7 准备完成后的日常启动

以下是部署、推理、舵机和校准均通过之后的启动方式。每个 SSH 窗口先 sudo -i。

终端一：

    cd /root/ros2_robot_arm
    source setenv.sh
    ros2 run dofbot_moveit dofbot_server

终端二：

    cd /root/ros2_robot_arm
    source setenv.sh
    if [ -f /usr/local/Ascend/ascend-toolkit/set_env.sh ]; then
        source /usr/local/Ascend/ascend-toolkit/set_env.sh
    elif [ -f /usr/local/Ascend/ascend-toolkit/latest/set_env.sh ]; then
        source /usr/local/Ascend/ascend-toolkit/latest/set_env.sh
    fi
    ros2 run dofbot_garbage_yolov5 block_cls

程序会自动复位并抓取。机械臂应固定，活动范围留空。需要堆叠时，先 Ctrl+C 停止分拣，再运行：

    ros2 run robot_arm_color_stacking color_stacking

不要同时运行分拣、堆叠、校准。正常结束先停止应用再停止服务。Ctrl+C 不保证撤销已经发送到扩展板的动作，不能当作硬件急停。

两个节点都已分别跑通后，可用一键启动替代两个窗口，不要额外保留重复服务：

    ros2 launch robot_arm_bringup block_cls_bringup.launch.py

堆叠的一键入口为 color_stacking_bringup.launch.py。

## 8 教程与源码中的容易混淆之处

- setenv.sh 使用相对目录，必须从 /root/ros2_robot_arm 执行；它本身不加载 CANN 环境。
- dofbot_server.cpp:20 硬编码 URDF 路径，仅修改 YAML 不会改变当前服务使用的路径。
- 代码用 Path(__file__).resolve() 推算安装资源路径。保持已成功的普通 colcon build，不按 Mac 说明贸然切换 --symlink-install。
- utils 缺少 __init__.py 会产生打包警告，但你已成功导入其中代码，不能把它认定为不动作原因。后续可补空文件并编译。
- 主程序对摄像头读取失败缺少检查，可能在 cv.resize 处报错。
- 部分 test 会调用真实抓取，不把 colcon test 或 pytest 全套运行作为无运动检查。
- 亮灯、pip 安装成功、五个包编译通过、ROS 服务出现，分别只验证其中一层。

现在先执行第 5 节检查，再结合机械臂独立供电和开关情况排查舵机。无需重新烧录系统或重装 ROS。
